# Hospitality operational authority

Business Operations owns physical stays, readiness observations, immutable folio obligations, actual cashier declarations and property-local business-day close. It reuses canonical property nodes, pool membership, reservations, accepted quote/financial lineage, tenant RBAC/MFA/approvals, shared protected storage and transactional outbox. It does not own a second room inventory, payment ledger, customer account authority or email/device provider.

Physical assignments bind one accepted reservation-room quantity slot to a same-property canonical ROOM/UNIT, exact civil nights and current node version. Unique active room nights and occupied-room indexes protect independent stays. Physical backing excludes outstanding overbooking. Assignment release is distinct from cancellation; an effective assignment blocks reservation cancellation/restructuring. A hard local hazard conservatively holds the affected commercial pool, including calendar availability, while preserving existing commitments. Dirty/clean/inspection evidence and current versions are authoritative; client-ready flags are not accepted.

Check-in commits reservation version, assignment occupancy, registered guest stay, frozen quote obligation, readiness history, audit and outbox together. Checkout releases actual occupancy and dirties the room. An independently approved debt departure retains SETTLEMENT_PENDING; it does not label money paid. Room moves preserve the existing stay/folio and accepted prices, release old remaining assignment nights, reserve compatible destination nights and retain old identity/history. Access references bind to individual assignments; provider outcomes remain UNKNOWN.

Folios conserve the gross accepted amount across quantity slots with exact integer quotient/remainder allocation. Later charges have unique actual source references. Corrections are bounded compensating items with exact independent approvals. Reconciliation consumes only existing signed Payment readback projections in this service database; aggregate allocation cannot exceed the authoritative receipt. Latest receipt expiry, reversal and remedy restrictions remove usable backing without erasing the original allocation. Collection and guarantees do not imply final settlement. Full extra-charge/mixed payer/remedy integration remains required. Accepted fiscal detail and explicit legacy review are described below.

A business day captures its timezone, policy version, cutoff wall time and resolved UTC deadline. Civil gaps move to the next valid minute; folds choose the latest occurrence. This prevents date regression and duplicate closes. Posting and closing use the common organisation transaction fence. Audit snapshots retain actual evidence digests, eligible exceptions need exact independent approval, hard exceptions cannot be waived, and close/report/rollover/outbox commit atomically. A changed cutoff applies when the next day opens. Historical postings are retained; no historical closing report is invented by migration.

Cashier expected movements come only from a signed Payment-owned attestation with delegated organisation, exact shift/property/currency and monotonic source version. Browser declarations cannot supply financial truth. Missing/expired receipts remain unknown, independent variance review preserves the actual count, and unknown reconciliation hard-blocks night close. Handover requires a distinct authorized receiver. The consumer contract is executable; a live Payment producer is not presently certified.

Offline clients supply stable operation IDs, original timestamps and expected versions. The server invokes the same online assignment/check-in/folio use cases with current authority. A savepoint isolates failed domain writes; the parent transaction persists the original failure and reconciliation task. Later retry/cancellation disposition never changes the original receipt into applied success.

Full group/event PMS, in-house extension/early departure stock reconciliation, automated audit/close/readiness/settlement/access workers and full CRM history/loyalty/recovery remain current internal implementation work. Rollback is application-based with retained migrations/evidence; drain or reconcile active assignments before using older images that cannot operate the new stay model. Prefer a compatible schema15 image or a forward fix. No agent VPS or production access is part of this process.

Group blocks now reference actual canonical held/confirmed room lines and never reserve a separate inventory pool. Rooming is an immutable versioned per-quantity-slot plan; latest revocation removes eligibility and check-in requires the exact current approved guest. Group batches invoke the same check-in/out use cases in one organisation-fenced transaction. Master bills aggregate current source folios/Payment evidence without duplicate receipts or payer reassignment. Facility events bind the existing facility reservation and capacity; source cancellation remains authoritative. Group/roster/master/event sources enter immutable night-audit digests, and missing current rooming slots block close.

Schema17 adds explicit post-departure folio closure and reservation COMPLETED only when every accepted physical quantity slot has departed, every source folio is closed and all balances are covered by fresh signed Payment settlement. Completed physical history is retained if later financial backing changes. Automatic closure is optional: a recent-MFA direct operator review captures immutable posting digest, membership/role and at most seven-day authority. Workers reload current membership, account, role, scope, restrictions and KYB using the same workforce loader/evaluator. Temporary grants cannot create these reviews; per-action MFA grants cannot authorize a sessionless worker. No human principal or fresh MFA timestamp is fabricated. Revocation is append-only and later postings invalidate the review.

The existing maintenance loop runs each domain with its own bounded context so an RMS failure cannot suppress hotel maintenance. Folio cursors provide fair bounded scanning without creating fake business versions. Expiring financial evidence queues only READBACK against the existing Payment binding, using the established durable lease/retry/fence queue. Broker/provider failure does not create a new collection. Lost backing moves a closed/settled folio to settlement pending and creates immutable source-specific exception evidence; verified closure resolves exceptions with audit/outbox history. Open exceptions appear in the front-desk board and hard-block night-audit close. This is not full automatic business-day/no-show/access or additional-charge collection completion; those remain listed current work.

Schema19 retains one immutable gross obligation and appends versioned fiscal detail, not financial postings. Original immutable quote/policy sources and exact integer allocation determine current detail. Missing legacy source quantities require explicit qualified evidence and independent net-only approval. Database guards enforce tenant/source identity, per-slot uniqueness, source budgets, immutable review history and transactional evidence. Final closure, night audit and CRM monetary eligibility check current detail; compensating corrections retain bad imported rows. The existing maintenance worker backfills valid sources and quarantines malformed ones without creating a second charge. Review API changes and current schema counts are additive.
